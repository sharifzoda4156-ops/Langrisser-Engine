# Лаборатория последовательных ударов

`apex_engine.hit_sequence_lab.simulate_hits(soldier_hp, hero_hp, hits)` —
изолированная модель учёта уже рассчитанных целых ударов. Для каждого удара
передаётся `source` (`hero` или `soldier`) и два значения: `to_soldier`,
`to_hero`. Вызывающий явно задаёт их порядок. Удар попадает в первого
живого солдата, иначе — в героя; излишек урона по одному солдату сгорает.
События возвращают цель, нанесённый и потерянный урон.

```python
from apex_engine.hit_sequence_lab import simulate_hits

hit = {"source": "hero", "to_soldier": 100, "to_hero": 100}
result = simulate_hits([180] * 10, 100, [hit] * 20)
assert result["hero_hp"] == 100
assert sum(e["excess"] for e in result["events"]) == 200
```

Числа взяты из [примера iamzhyk](https://levelone.com.hk/lg-damages/).
Возможность менять число, порядок и урон ударов показывает, что общий пул HP
и покадровая модель дают разные результаты. Направление выбора цели,
скорость анимации, округление, криты, щиты, восстановление солдат и реальное
число сегментов остаются **непроверенными допущениями**. Количество солдат
0–12 и максимум 80 ударов — только границы этого исследовательского API.

Модуль не вызывается ни стендом, ни `combat-pools-lab-v1`, ни
`formula_lab.py`. Запуск тестов: `python -m unittest tests.test_hit_sequence_lab -v`.
